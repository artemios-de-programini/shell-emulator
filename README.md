# Эмулятор командной строки UNIX-подобной ОС

Учебный проект по дисциплине «Конфигурационное управление», вариант №8.
Эмулятор повторяет поведение командной строки UNIX-подобной операционной
системы: принимает команды в графическом окне, раскрывает переменные
окружения реальной ОС и работает с виртуальной файловой системой.

## Требования

- Python 3.10 или новее;
- библиотека `tkinter` (входит в стандартную поставку Python для Windows и
  macOS, в Linux устанавливается пакетом `python3-tk`);
- внешние зависимости проекту не нужны.

## Запуск

```bash
./run.sh
```

Скрипт `run.sh` доступен для Linux и macOS, скрипт `run.bat` — для Windows.
Оба скрипта принимают те же параметры, что и сама программа:

```bash
./run.sh --vfs ./vfs_root --script ./scripts/demo.txt
```

Прямой запуск без скриптов-обёрток:

```bash
python3 src/main.py --vfs ./vfs_root --script ./scripts/demo.txt
```

## Параметры командной строки

| Параметр   | Обязательный | Значение по умолчанию | Назначение                       |
|------------|--------------|-----------------------|----------------------------------|
| `--vfs`    | нет          | `./vfs/standard`      | каталог виртуальной файловой системы |
| `--script` | нет          | не задан              | стартовый скрипт эмулятора       |
| `--headless` | нет        | выключен              | запуск без графического интерфейса |

Параметр `--headless` используется автотестами и демонстрационными
скриптами: эмулятор выполняет стартовый скрипт и печатает диалог в
стандартный поток вывода, не открывая окно.

## Отладочный вывод параметров

При запуске эмулятор печатает все заданные параметры — и в стандартный
поток вывода, и в окно графического интерфейса:

```text
Emulator configuration
  vfs      /home/student/shell-emulator/vfs/standard [directory]
  script   /home/student/shell-emulator/scripts/demo.txt [ok]
  mode     GUI
  entries  4 files, 3 directories
```

## Виртуальная файловая система

Источником виртуальной файловой системы служит обычный каталог на диске.
При запуске эмулятор один раз читает этот каталог и строит дерево узлов
в памяти. Дальше все команды работают только с этим деревом: исходный
каталог не изменяется и повторно не читается.

Если источник недоступен, эмулятор сообщает об ошибке и завершается с
кодом `3`:

```text
shell-emulator: VFS error: directory not found: /home/student/absent
```

Сообщаются три вида ошибок загрузки: каталог не найден, путь указывает на
файл вместо каталога и файл внутри каталога имеет неверный текстовый
формат (не UTF-8).

В репозитории лежат три набора данных, которые проверяют разные варианты
виртуальной файловой системы:

| Каталог          | Содержимое                                        |
|------------------|---------------------------------------------------|
| `vfs/minimal`    | один файл в корне                                 |
| `vfs/standard`   | файл в корне и два уровня вложенных каталогов      |
| `vfs/deep`       | три уровня вложенных каталогов и файлы на каждом   |

```bash
./run.sh --vfs ./vfs/minimal
./run.sh --vfs ./vfs/deep
```

## Стартовые скрипты

Стартовый скрипт — обычный текстовый файл, в каждой строке которого
записана одна команда эмулятора. Правила выполнения:

- пустые строки и строки, начинающиеся с `#`, пропускаются;
- команда и её вывод отображаются в окне так же, как при ручном вводе;
- выполнение останавливается на первой команде, завершившейся ошибкой,
  и в окне появляется сообщение `script: stopped at command '<команда>'`.

Пример стартового скрипта `scripts/demo.txt`:

```text
# Startup script: REPL and the basic commands of the emulator.
ls
cd folder1
ls -l
cat nested_folder/secret.txt
du
cal
cd ..
exit
```

Скрипты реальной ОС из каталога `scripts` запускают эмулятор с разными
параметрами:

| Скрипт                       | Что проверяет                                  |
|------------------------------|------------------------------------------------|
| `scripts/start_gui.sh`       | оба параметра и графический интерфейс          |
| `scripts/start_headless.sh`  | оба параметра и режим без интерфейса           |
| `scripts/start_minimal.sh`   | минимальный набор данных VFS                   |
| `scripts/start_deep.sh`      | три уровня вложенности каталогов               |
| `scripts/start_errors.sh`    | обработку ошибок стартового скрипта            |

## Команды

| Команда          | Синтаксис               | Назначение                         |
|------------------|-------------------------|------------------------------------|
| `ls`             | `ls [-l] [путь]`        | содержимое каталога                |
| `cd`             | `cd [путь]`             | смена текущего каталога            |
| `cat`            | `cat файл...`           | вывод содержимого файлов           |
| `cal`            | `cal [месяц] [год]`     | календарь месяца или года          |
| `du`             | `du [-a] [-h] [путь]`   | размеры каталогов и файлов         |
| `exit`           | `exit [код]`            | выход из эмулятора                 |

Команда `ls` печатает по одному элементу в строке и добавляет `/` к
каталогам, команда `du` разделяет размер и путь символом табуляции.

```text

cat: absent.txt: No such file or directory
script: stopped at command 'cat absent.txt'
```

## Сравнение со штатными средствами UNIX

| Команда | Совпадает                                   | Отличается                                        |
|---------|---------------------------------------------|---------------------------------------------------|
| `ls`    | сортировка, пометка каталогов, `-l`         | один элемент в строке вместо колонок, нет цветов  |
| `cd`    | относительные и абсолютные пути, `..`, `~`  | меняется только виртуальный каталог               |
| `cat`   | конкатенация файлов, коды ошибок            | не читает стандартный вход                        |
| `cal`   | месяц, год, проверка диапазонов             | английские названия месяцев, неделя с понедельника |
| `du`    | рекурсивные суммы, `-a`, `-h`, порядок строк| байты содержимого вместо блоков диска             |

## Реализованные этапы

### Этап 1. REPL

- приложение работает в форме графического интерфейса (Tkinter);
- заголовок окна содержит имя виртуальной файловой системы;
- парсер командной строки раскрывает переменные окружения реальной ОС
  (`$HOME`, `${USER}`), поддерживает одинарные и двойные кавычки, а также
  экранирование обратной косой чертой;
- ошибки сообщаются пользователю: неизвестная команда, незакрытая кавычка,
  неверный код завершения;
- команды `ls` и `cd` реализованы как заглушки и печатают своё имя и
  полученные аргументы;
- команда `exit` завершает работу эмулятора.

### Этап 2. Конфигурация

- параметры командной строки `--vfs` и `--script` описаны в таблице выше;
- при запуске печатается отладочный вывод всех заданных параметров;
- стартовый скрипт выполняется с остановкой на первой ошибке и с показом
  ввода и вывода;
- в каталоге `scripts` лежат скрипты реальной ОС, которые вызывают
  эмулятор и проверяют все параметры командной строки.

### Этап 3. Виртуальная файловая система

- дерево файлов и каталогов строится в памяти при запуске и дальше не
  зависит от диска;
- источником дерева служит каталог, заданный параметром `--vfs`;
- ошибки загрузки (каталог не найден, путь указывает на файл, файл не
  является текстом UTF-8) выводятся в стандартный поток ошибок, а
  эмулятор завершается с кодом `3`;
- в репозитории лежат три набора данных: минимальный, обычный и с тремя
  уровнями вложенности;
- скрипты `scripts/start_minimal.sh` и `scripts/start_deep.sh` проверяют
  работу с разными наборами данных.

### Этап 4. Основные команды

- реализована логика команд `ls` и `cd`: сортировка, длинный формат,
  относительные и абсолютные пути, `..`, `~`, проверка типа узла;
- добавлены команды `du`, `cal` и `cat` с разбором аргументов и
  сообщениями об ошибках;
- стартовый скрипт `scripts/demo.txt` демонстрирует все команды этапа;
- вывод команд и коды ошибок сопоставлены со штатными средствами UNIX,
  отличия перечислены в таблице выше.

## Структура репозитория

```text
src/
  lexer.py      разбор командной строки и раскрытие переменных
  vfs.py        загрузка виртуальной файловой системы в память
  commands.py   реализации команд
  shell.py      диспетчеризация команд и статус последней команды
  state.py      состояние сессии: каталог, окружение, файловая система
  config.py     отладочный вывод параметров запуска
  gui.py        графический интерфейс
  main.py       точка входа
tests/          модульные тесты (unittest)
vfs/            три набора данных виртуальной файловой системы
scripts/        стартовые скрипты и скрипты запуска
run.sh          скрипт запуска для Linux и macOS
run.bat         скрипт запуска для Windows
```

## Тестирование

```bash
python3 -m unittest discover -s tests -v
```
